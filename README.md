# 集結計算機 / irony

GitHub Pagesで配信する静的アプリです。ビルドやnpm installは不要です。
ローカルでは `python3 -m http.server 8000` を実行し、`http://localhost:8000` を開いてください。
ES Modulesを使うため、HTMLファイルの直接ダブルクリックでは動作しません。

## 変更する場所

| 変更内容                                           | ファイル               |
| -------------------------------------------------- | ---------------------- |
| ページ・入力欄のHTML                               | `index.html`           |
| 画面イベント・集結主一覧・設定保存・画面の組み立て | `app.js`               |
| 着弾時刻ページ                                     | `js/ui/landing.js`     |
| スイッチページ                                     | `js/ui/switch.js`      |
| 時刻の計算式                                       | `js/domain/timing.js`  |
| 座標別の行軍時間と検索                             | `js/domain/march.js`   |
| プレイヤーIDからの取得・代替名簿取得               | `js/api/players.js`    |
| Firebase同期                                       | `js/api/rally-sync.js` |
| 接続先などの設定                                   | `js/config.js`         |
| Oracle中継用Worker（別途デプロイ）                 | `worker/worker.js`     |

`app.js` がAPIと計算関数を読み込み、結果を画面に反映します。
`js/api` と `js/domain` はDOMや画面のIDを参照しません。
APIを変更するときは、下記の入出力を維持するか、API層で変換してください。
UI側でレスポンス形式やFirebaseの保存パスを扱わない構成です。

## APIの入出力

| 操作                                       | 入力                                            | 出力                                       |
| ------------------------------------------ | ----------------------------------------------- | ------------------------------------------ |
| `createPlayerApi().getPlayer(id)`          | ゲームIDの文字列                                | `{name, avatar}` / 見つからなければ `null` |
| `connectRallySync(config)`                 | Firebase設定                                    | 接続済み同期API                            |
| `publishRoster(names)`                     | 名前の配列                                      | Promise                                    |
| `subscribeRoster(callback)`                | 名前の配列を受け取る関数                        | 購読解除関数                               |
| `publishDepartures(records, previousKeys)` | `{key, name, departureTime}` の配列と旧キー配列 | Promise                                    |
| `subscribeMember(key, callback)`           | エンコードした名前と記録を受け取る関数          | 購読解除関数                               |
| `removeMember(key)`                        | エンコードした名前                              | Promise                                    |
| `now()`                                    | なし                                            | サーバー時刻差を反映したUnixミリ秒         |

通信エラーはPromiseの拒否としてUIへ返します。通知文言と画面表示はUI側が決めます。
既存の `activeRally/roster`、`activeRally/members` と保存形式は維持しています。
名前のキーは従来どおり `encodeURIComponent(name)` です。
プレイヤー取得は従来どおり直接APIを試し、通信失敗時に `members.json` へフォールバックします。
Workerへの接続先変更・Workerのデプロイは、この整理には含みません。

## CSS

`style.css` は読み込み順を定義する入口です。

| ファイル                | 編集するもの                                          |
| ----------------------- | ----------------------------------------------------- |
| `css/00-base.css`       | 共通トークン・初期値・汎用要素                        |
| `css/10-members.css`    | 集結主一覧・座標・ペットの基本部品                    |
| `css/20-pages.css`      | ページ切替・トースト・候補表示                        |
| `css/30-layout.css`     | 画面レイアウト・時間編集・端末設定                    |
| `css/40-responsive.css` | モバイル向けの一覧・設定・時計の差分                  |
| `css/50-widgets.css`    | 時計・メニュー・集結主の部品と状態          |
| `css/60-themes.css`     | ライト・ダークの配色トークンと互換エイリアス                 |
| `css/70-components.css` | 3タブ共通の設定行・計算ボタン・結果・コピープレビュー |

共通部品の寸法は `00-base.css` の `--component-*`、ルール本体は
`70-components.css` にあります。修正時はこの定義を編集し、他のファイルの末尾に
同じ部品の上書きを追加しないでください。共通部品のルールに `!important` は不要です。
テーマを変えるときは `60-themes.css` の変数を編集します。配置指定はテーマに含めません。

同じセレクター・同じ条件で後の指定に置き換わっていた宣言、使われなくなった変数と
アニメーションを除去しています。カード等の一般ルールは、専用定義を持つ
コピープレビューを `:where(:not(.copy-preview-card))` で対象外にしています。

現在の見た目を維持するため、王城決戦のプレビューヘッダーの高さ、準備時間の補助文字、
スイッチのネイティブ選択などのページ差分は、共通ファイル内に明示して残しています。
時計・集結主一覧等は個別の部品・状態・画面幅のルールも引き続き使います。

## 確認

Node.js 18以降で `npm test` を実行します。外部サービスへの接続・書き込みは行いません。
テストは日付をまたぐ着弾計算、行軍バフの組み合わせ、同期データの形式、
購読解除、プレイヤー取得失敗時の代替処理を確認します。

画面変更時は3タブ、2テーマ、名前・ID入力、座標とバフの連動、
保存からの復元、行の追加・削除も確認してください。

## CSSの変更前後を比較する

任意でPlaywrightとブラウザを用意し、変更前のGitリビジョンを指定します。
公開用のビルドや依存関係のインストールは引き続き不要です。

```sh
npm install --no-save playwright
npx playwright install chromium
npm run test:css -- <変更前のコミットSHA>
```

`check-css.cjs` は変更前のファイルを一時領域に取り出し、現在の作業ツリーと比較します。
320px・390px・1024px、2テーマで、3タブの通常・無効化・キーボードフォーカス状態、計算結果、
プレビューと集結主設定、時間編集、メニューの計90通りを確認します。
表示中の要素と疑似要素の寸法・色・書体・余白・配置等を比較します。
アニメーションは比較中に無効化し、時刻に依存するコピー完了通知は非表示にして計測します。
外部通信は遮断し、本番Firebaseや外部APIへの書き込みは行いません。
差がある場合は、出力された一時ファイルで内容を確認できます。

実機Safari・iPhoneのPiP・通知の検証と公開サイトへのデプロイは別途必要です。

## 動作の不具合を再確認する

Playwrightとブラウザを用意した環境で `npm run test:browser` を実行します。
独自の集結・準備時間の復元、準備時間0秒の着弾計算、破損した履歴・ペット情報でも
起動とタブ切替・スイッチ計算が動くこと、テーマの移行・切替・保存を9ケースで確認します。
外部通信は遮断し、本番Firebaseや外部APIへ接続しません。

独自設定は選択肢を復元してから選択します。無効な履歴・ペット情報は読み込み時に
除外し、有効なデータを引き続き利用します。準備時間の0秒を初期値で上書きしません。

## 今回の検証結果

- `npm test`: 7件成功。
- `test:css`: Chromiumで、変更前と現在の225通りの比較が成功。
- `test:browser`: 修正前に失敗した6ケースが、修正後はすべて成功。
- 画面サイズは320px・390px・1024px、テーマは5種類。
- 通常表示に加え、無効化・キーボードフォーカス・計算結果・プレビュー展開・集結主設定・時間編集・メニューを確認。
- 本番サービスへの書き込みと公開サイトへのデプロイは未実施。

初回の自動操作デモとiPhone向けのショートカット説明文は削除しました。時計・端末同期・PiPショートカットの機能は引き続き使えます。

テーマはライト・ダークの2種類です。旧カラーの保存設定はライトとして表示します。カウントダウンの背景・影はなくし、計算・コピー完了は160msの短いフェードで示します。「動きを減らす」の端末設定ではアニメーションを停止します。
